# Архитектура AWG-RT

## Компоненты

```
┌─────────────────────────────────────────────────────────────┐
│  Главный сервер (panel/)                                     │
│                                                                │
│  ┌──────────┐   ┌───────────┐   ┌────────┐                  │
│  │  panel   │──▶│ PostgreSQL│   │ Redis  │                  │
│  │ (FastAPI)│   └───────────┘   └────────┘                  │
│  └────┬─────┘                        ▲                       │
│       │                              │                       │
│       │  TTL-конфиги пиров (48ч),    │                       │
│       │  не персистятся в Postgres ──┘                       │
└───────┼────────────────────────────────────────────────────┘
        │ HTTP + Bearer token
        │ (agent_token per node)
        ▼
┌─────────────────────────────────────────────┐
│  Нода (node-agent/) — например my-awg-node│
│                                                 │
│  ┌────────────┐         ┌──────────────────┐  │
│  │ node-agent │──exec──▶│  amnezia-awg2     │  │
│  │ (FastAPI)  │  через  │  (AmneziaWG 2.0)  │  │
│  └────────────┘  Docker └──────────────────┘  │
│                  socket                        │
└─────────────────────────────────────────────┘
```

Панель и агент — **разные контейнеры на разных ролях**:
- Панель живёт на главном сервере, знает обо всех нодах и роутерах
- На каждой AWG-ноде — свой `node-agent` + свой `amnezia-awg2`, они ничего не знают друг о друге кроме токена авторизации

## Почему agent и awg-контейнер разделены

Обсуждалось явно: agent получает доступ к `/var/run/docker.sock` (что эквивалентно root на хосте), но это ограничено **программно** — `AWG_CONTAINER_NAME` зашит в настройках агента при деплое и никогда не принимается из API-запроса. Даже если токен агента скомпрометирован, атакующий не может выполнить `docker exec` в произвольном контейнере хоста — только в том одном, что прописан в `.env` этой ноды.

## Модель хранения ключей

| Что | Где хранится | Кто генерирует |
|---|---|---|
| Приватный ключ сервера (ноды) | Только внутри `amnezia-awg2` контейнера, в файле `awg0.conf` | node-agent при `/server/init` |
| Публичный ключ сервера | Postgres (`nodes.public_key`) + сама нода | node-agent → отдаёт панели |
| Приватный ключ клиента (пира) | Транзитом через панель → пользователю; кэш в Redis с TTL 48ч; **никогда** в Postgres | node-agent при `POST /peers` |
| Публичный ключ клиента | Postgres (`peers.public_key`), хранится бессрочно | node-agent → отдаёт панели |

Почему приватный ключ клиента не в Postgres: он неизбежно должен попасть к пользователю (иначе как ему настроить устройство), поэтому полное нехранение невозможно. Компромисс — короткоживущий кэш в Redis, чтобы администратор мог передёрнуть конфиг в течение 48 часов, если ошибся при сохранении, но после этого окна ключ исчезает полностью — единственный путь восстановления — создать нового пира.

## Мониторинг

Панель опрашивает `/server/status` каждой ноды раз в `MONITORING_INTERVAL_SECONDS` (по умолчанию 180 сек / 3 мин). Статус роутера (`routers.awg_link_status`) выводится из времени последнего хендшейка соответствующего пира:

```
< 5 минут (HANDSHAKE_STALE_AFTER_SECONDS)   → up
5–15 минут (HANDSHAKE_DOWN_AFTER_SECONDS)   → stale
> 15 минут, или нода недоступна             → down
```

Если сама нода не отвечает — все привязанные к ней роутеры переходят в `unknown` (не в `down`), потому что в этом случае мы не знаем реального состояния линка, а не знаем, что он оборвался.

## Remote-доступ к роутерам — сознательно НЕ реализован здесь

AWG-RT не дублирует `owrt-remote`/`netcraze-remote` — только хранит справочную ссылку (`routers.remote_hub_url`) на карточку роутера в уже существующем хабе. Если нужно зайти на роутер руками — переход по этой ссылке в соответствующую панель.

## Технологический стек

- **Панель**: FastAPI + SQLAlchemy 2.0 (async) + PostgreSQL + Redis + Alembic
- **Веб-интерфейс**: Jinja2 (серверный рендеринг) + HTMX (частичные обновления без полного реролла) + Alpine.js (мелкая интерактивность) + Tailwind CSS (через CDN, без сборки)
- **node-agent**: FastAPI + docker-py (управление AWG-контейнером через Docker socket)
- **Аутентификация**: JWT (bcrypt-хэши паролей), одна и та же схема токена работает и как Bearer-заголовок (для внешних интеграций), и как cookie-сессия (для веб-интерфейса)
