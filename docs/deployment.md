# Развёртывание

## Панель (один раз, на главном сервере)

Скопируйте и выполните целиком — клонирует только папку `panel/` (без исходников агента), ставит всё под отдельным сервисным аккаунтом (не под root), в конце убирает исходный клон целиком (он больше не нужен — рабочая копия уже лежит в `/opt`):

```bash
git clone --filter=blob:none --sparse --depth 1 https://github.com/beverlypillzz-collab/Vodkinnet-AWG-RT.git && cd Vodkinnet-AWG-RT && git sparse-checkout set panel && cd panel && sudo ./install.sh && cd ../.. && rm -rf Vodkinnet-AWG-RT
```

Скрипт сам:
1. Ставит Docker, если его нет
2. Создаёт системный аккаунт `awgrt` (без интерактивного входа, только для запуска контейнеров) и добавляет его в группу `docker`
3. Копирует файлы панели в `/opt/vodkinnet-awg-rt`, отдаёт во владение этому аккаунту
4. Генерирует `.env` со случайными `POSTGRES_PASSWORD` и `JWT_SECRET` (если `.env` уже существует в `/opt/vodkinnet-awg-rt` — переиспользует его, не трогает)
5. Собирает и поднимает `postgres`, `redis`, `panel` **от имени аккаунта `awgrt`**, не root (миграции Alembic накатываются автоматически при старте контейнера панели)
6. Ждёт, пока панель ответит на `/docs`
7. Предлагает создать первого админа интерактивно
8. В конце подсказывает, что исходную папку клона можно удалить — всё нужное уже лежит в `/opt/vodkinnet-awg-rt`

### Про сервисный аккаунт — честно о границах

Членство в группе `docker` фактически равносильно root на хосте (сокет Docker позволяет смонтировать корень хоста в контейнер) — это **не** песочница и не полная изоляция от рута. Что аккаунт `awgrt` реально даёт:
- Нет интерактивного root-логина для повседневной работы с панелью
- Файлы и секреты (`.env`) принадлежат узкому аккаунту, а не root — сторонний непривилегированный процесс/пользователь их не прочитает
- Изоляция от посторонних root-уровня cron/скриптов, которые могли бы случайно задеть файлы панели

Это разделение обязанностей, а не тюрьма для скомпрометированного процесса.

**Управление после установки** — от имени `awgrt`, не root:
```bash
sudo -u awgrt docker compose -f /opt/vodkinnet-awg-rt/docker-compose.yml logs -f panel
sudo -u awgrt docker compose -f /opt/vodkinnet-awg-rt/docker-compose.yml restart panel
```

**После установки** панель слушает `127.0.0.1:8000` — снаружи не торчит специально. Поставьте перед ней свой существующий nginx/Caddy с TLS:

```nginx
server {
    listen 443 ssl;
    server_name your-panel-domain.example;
    # ... ваши обычные SSL-директивы (acme.sh/certbot) ...
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## Нода (на каждом AWG-сервере, например `nodert-vodkinnet`)

Скопируйте и выполните целиком — клонирует только `node-agent/`, ставит и убирает служебные git-данные:

```bash
git clone --filter=blob:none --sparse --depth 1 https://github.com/beverlypillzz-collab/Vodkinnet-AWG-RT.git && cd Vodkinnet-AWG-RT && git sparse-checkout set node-agent && cd node-agent && sudo ./install.sh && cd .. && rm -rf .git
```

Скрипт спросит:
- Имя ноды (только для справки в выводе)
- UDP-порт для AmneziaWG (по умолчанию `55632`)
- Публичный адрес ноды (можно оставить пустым — тогда панель сама подставит `hostname` при выдаче клиентских конфигов)

И дальше сам:
1. Ставит Docker, если его нет
2. Генерирует `.env` со случайным `AGENT_TOKEN`
3. Собирает `amnezia-awg2` (на базе `amneziavpn/amneziawg-go:2.0.0`) и `node-agent`
4. Поднимает оба контейнера
5. Ждёт, пока agent ответит на `/health`
6. **Печатает данные для добавления ноды в панель**: hostname, agent_port, listen_port, agent_token — скопируйте сразу, токен больше не выводится

### Сетевые требования на ноде

- `{agent_port}/tcp` (по умолчанию `8181`) — доступен **только** с IP панели (firewall allowlist), никогда не наружу
- `{listen_port}/udp` (по умолчанию `55632`) — открыт в интернет, это сам VPN-трафик

Пример правила для UFW:
```bash
ufw allow from <IP-панели> to any port 8181 proto tcp
ufw allow 55632/udp
```

## Почему именно AmneziaWG 2.0, а не 3.1

Официальное приложение Amnezia с версии, требующей протокол 3.1, отказывается работать с клиентами на OpenWrt и Keenetic/Netcraze — эти прошивки пока не поддерживают протокол 3.1 нативно (подтверждено официальной документацией Amnezia). Пока это не изменится на стороне разработчиков прошивок, весь флот стоит на 2.0. Тег образа `amneziavpn/amneziawg-go:2.0.0` зашит в `node-agent/amnezia-awg2/Dockerfile` явно — при обновлении в будущем меняется одна строка `FROM`.

## Добавление ноды в панель

После установки ноды — залогиньтесь в панель, откройте форму создания ноды и укажите то, что вывел `install.sh` на ноде:

```json
{
  "name": "nodert-vodkinnet",
  "hostname": "<публичный IP или домен ноды>",
  "agent_port": 8181,
  "agent_token": "<из вывода install.sh>",
  "listen_port": 55632,
  "awg_params": { "Jc": 4, "Jmin": 40, "Jmax": 70 }
}
```

Панель сама вызовет `/server/init` на ноде и сохранит публичный ключ.

## Откат / переустановка ноды

`install.sh` безопасно перезапускать — если `.env` уже существует, он не трогается (чтобы не потерять `agent_token`, уже зарегистрированный в панели). Если нужно полностью пересоздать ноду с нуля:

```bash
docker compose down -v
rm .env
sudo ./install.sh
```

Это сгенерирует новый `agent_token` — не забудьте обновить его в панели (или удалить старую запись ноды и создать новую).
