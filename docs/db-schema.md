# Схема базы данных

Источник истины — `panel/src/db/models.py` и `panel/alembic/versions/0001_initial_schema.py`. Этот файл объясняет **зачем** каждое поле существует; если меняете модель, обновите и этот файл в том же коммите.

## `nodes` — AmneziaWG-серверы

| Поле | Зачем |
|---|---|
| `agent_token` | Секрет для авторизации панели на этой ноде. Хранится в открытом виде в Postgres (не хэш) — панели нужно **предъявить** его агенту, а не только проверить, поэтому хэширование бессмысленно, но доступ к БД панели должен быть так же защищён, как доступ к самим нодам |
| `public_key` | Nullable — заполняется после успешного `/server/init`. `null` значит "нода создана в панели, но агент ещё не инициализирован" |
| `awg_params` | JSONB, параметры обфускации протокола (Jc/Jmin/Jmax/S1/S2/H1-H4) на уровне интерфейса всей ноды |
| `status` | `unknown` / `online` / `offline` — обновляется monitoring-сервисом каждые 3 минуты |

## `routers` — клиентские роутеры (OpenWrt/Keenetic)

| Поле | Зачем |
|---|---|
| `remote_hub` / `remote_hub_url` | Справочная ссылка на существующий хаб (`owrt-remote`/`netcraze-remote`) — AWG-RT сознательно не дублирует remote-доступ, только хранит, где искать |
| `awg_link_status` | `up`/`stale`/`down`/`unknown` — выводится из `last_handshake_at` привязанного пира по порогам 5/15 минут |

## `peers` — WireGuard/AmneziaWG пиры

| Поле | Зачем |
|---|---|
| `router_id` | Nullable — пир может существовать без привязки к учтённому в системе роутеру (разовое тестовое подключение) |
| `public_key` | Хранится постоянно — нужен для сопоставления с ответом `wg show` от ноды |
| **Приватный ключ клиента НЕ хранится здесь** | См. `docs/architecture.md` — только транзитом через Redis с TTL |
| `revoked_at` | Soft-delete — история кто-когда был подключён сохраняется, не теряется при отзыве |
| `UNIQUE(node_id, public_key)` | Один и тот же публичный ключ не может дважды числиться пиром одной ноды |

## `admins` / `audit_log`

Простые справочные таблицы: учётки операторов панели и append-only журнал действий.

## Индекс/связи

```
nodes 1───* peers *───1 routers (router_id nullable, ON DELETE SET NULL)
                 │
                 └─ ON DELETE CASCADE от nodes (удалили ноду → удалились все её пиры)
```
